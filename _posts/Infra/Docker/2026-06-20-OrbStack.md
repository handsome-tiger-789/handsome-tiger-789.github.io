## OrbStack 이란?

macOS 전용으로 만들어진 경량 컨테이너/리눅스 VM 실행 환경.<br>
Docker Desktop과 동일한 Docker CLI 호환성을 제공하면서도 훨씬 적은 리소스를 사용한다.<br>
<br>
기존 Docker Desktop이 Mac에서 메모리를 과도하게 점유하는 문제(특히 Apple Silicon에서 VM 오버헤드)를 해결하기 위해 등장했다.


## Docker Desktop vs OrbStack

| 항목         | Docker Desktop  | OrbStack            |
| ---------- | --------------- | ------------------- |
| 메모리 사용량    | 2~4GB 이상 점유     | 평균 100~500MB        |
| 부팅 속도      | 수 초 ~ 십 수 초     | 1~2초 이내             |
| CPU 점유     | idle 시에도 사용량 있음 | idle 시 거의 0에 가까움    |
| 디스크 사용     | 큼 (VM 디스크 고정)   | 동적 할당, 압축 효율 좋음     |
| 배터리 소모     | 큼               | 작음                  |
| Rosetta 지원 | 지원              | 지원 (x86 컨테이너 실행 빠름) |
| 라이선스       | 대규모 기업 유료       | 개인 무료 / 상업 유료       |

> **Rosetta 지원이란?**<br>
> Apple Silicon(M1/M2/M3/M4)은 ARM64 아키텍처이지만, Docker 이미지의 상당수는 여전히 x86_64(amd64)로 배포된다.<br>
> Rosetta는 Apple이 제공하는 x86 → ARM 변환 계층으로, 이를 활용하면 amd64 컨테이너를 QEMU 에뮬레이션 대비 훨씬 빠르게(거의 네이티브 수준) 실행할 수 있다.<br>
> 즉 **"Rosetta 지원 = ARM Mac에서도 amd64 이미지를 실용적인 속도로 돌릴 수 있다"** 는 의미.



## 주요 특징

1. **Docker 완전 호환**
   - `docker`, `docker compose` 명령어를 그대로 사용 가능
   - 기존 Dockerfile, compose 파일 수정 불필요

2. **Linux VM 지원**
   - 별도의 UTM, Multipass 없이 Ubuntu, Debian, Arch 등 리눅스 머신을 즉시 생성
   - Mac 파일 시스템과 자동 마운트

3. **Kubernetes 내장**
   - 토글 한 번으로 K8s 클러스터 활성화 (k3s 기반, 매우 가벼움)
   - kubectl 즉시 사용 가능

4. **네트워크 자동 도메인**
   - 컨테이너마다 `<name>.orb.local` 도메인이 자동 부여되어 호스트에서 바로 접근 가능<br>(해당 기능은 문제가 있어 테스트 해보진 못함)

4. **GUI 제공**
   - 컨테이너/이미지/볼륨/로그를 시각적으로 관리
   - Docker Desktop UI보다 가볍고 반응 빠름


## 설치

```bash
brew install --cask orbstack
```

설치 후 Docker Desktop은 종료하거나 제거 권장 (소켓 충돌 방지).<br>
`docker context` 가 자동으로 OrbStack으로 전환된다.

```bash
docker context ls
```


## 한계점

- macOS 전용 (Windows/Linux 미지원)
- 회사/팀 단위 상업적 사용은 유료 라이선스 필요
- Docker Desktop의 일부 GUI 확장(Extension)은 사용 불가


## 개인 경험

- 실제로 전환 후 **압축된 메모리(Compressed Memory)** 사용량이 압도적으로 줄어들었다.<br>항상 부족하던 Mac 메모리가 눈에 띄게 여유로워진 것이 가장 큰 체감 차이였다.
- **minikube 대체 가능 여부**는 아직 검증하지 못함.<br>OrbStack에 K8s 토글 기능이 내장되어 있다고 하지만 직접 구성해보지 않았고,<br>minikube에서 제공하던 대시보드(`minikube dashboard`) 수준의 시각화가 그대로 가능한지는 확인 필요.
- 현재까지는 Docker Desktop의 단순 대체용으로만 사용 중이며, K8s 워크플로 이관은 추후 테스트 예정.


## 결론

> 개인 개발 환경에서 Mac 배터리/메모리 문제로 Docker Desktop이 부담된다면<br>
> OrbStack으로 갈아타는 것이 거의 무손실에 가깝다.<br>
> CLI 호환성이 그대로이기 때문에 워크플로 변경 없이 전환 가능하다.
